プロジェクト概要

▼

目的

中小企業の経理担当者が紙・PDFで受け取る請求書を、AIによるOCRで自動読み取りし、 確認・承認・ステータス管理をクラウド上で完結できる社内Webアプリケーションを構築する。 現状の「Excelによる手動転記」を廃し、ヒューマンエラー削減と処理速度向上を実現する。

主要機能

  • Cognito認証によるログイン（メールアドレス＋パスワード）
  • PDF請求書のS3アップロード（OCRエンジン選択：Textract / Claude Vision）
  • OCR自動読み取り結果の確認・手修正・承認申請
  • 承認フロー（承認 / 差し戻し / 再確認申請）
  • 請求書ステータス一覧・CSV出力・PDF閲覧
  • ダッシュボード（統計・差し戻し処理待ちタスク）
  • SESメール通知（承認・差し戻し時）
  • 管理者設定（会社情報・OCR設定・承認ルール・通知設定・ユーザー管理）

システム概要図

ユーザー（ブラウザ）
  │
  ├─ AWS Amplify ── フロントエンド（HTML/CSS/JS）
  │
  ├─ Amazon Cognito ── 認証（JWT idToken）
  │
  ├─ API Gateway (HTTPS)
  │     ├─ GET  /invoices          → list_handler (Lambda)
  │     ├─ POST /invoices/presign  → presign_handler (Lambda)
  │     ├─ POST /invoices/confirm  → ocr_confirm_handler (Lambda)
  │     └─ POST /approval          → approval_handler (Lambda)
  │
  ├─ Amazon S3 ── 請求書PDF保管（Presigned URL）
  │     └─ S3トリガー → ocr_trigger (Lambda)
  │           ├─ Amazon Textract（OCRエンジン: textract）
  │           └─ Claude Vision API（OCRエンジン: claude）
  │
  ├─ Amazon DynamoDB
  │     ├─ Invoices テーブル
  │     ├─ ApprovalLogs テーブル
  │     └─ Users テーブル
  │
  ├─ AWS SES ── メール通知 → notify_sender (Lambda)
  └─ AWS SSM Parameter Store ── Anthropic APIキー管理

▼

機能要件

▼

3.1 ログイン・認証

  • Cognito User Pool によるメールアドレス＋パスワード認証
  • JWT idToken を sessionStorage.token に保存し、以後のAPI呼び出しで使用
  • ログイン成功後、Lambda コールドスタート解消のためウォームアップfetchを実行（800ms後にダッシュボードへ遷移）
  • 未ログイン状態でのページアクセスはトップへリダイレクト
  • ログアウト機能あり（sessionStorage クリア）

3.2 PDFアップロード（upload.html）

  • PDFファイルのドラッグ＆ドロップまたはファイル選択
  • OCRエンジン選択（ラジオボタン: Textract / Claude Vision）
  • Presigned URL経由でS3に直接アップロード
  • アップロード後、S3トリガーで ocr_trigger Lambda が自動起動
  • ベンダー名・請求書番号・金額・支払期限などのメタ情報を入力可能（任意）

3.3 OCR結果確認（ocr-confirm.html）

  • OCR処理中のステータスをポーリングで取得（初回1秒、以降2秒間隔）
  • OCR完了後、読み取り結果（ベンダー名・請求書番号・金額・支払期限・摘要）を表示
  • 各フィールドを手動修正可能
  • 「確認・承認申請」ボタンで ocr_confirm APIを呼び出し、ステータスを pending_approval に更新
  • 「再処理」ボタン（スタブ・未実装）

3.4 承認フロー（approval.html）

  • 4タブ構成: 承認待ち / 承認済み / 差し戻し / 全て
  • 承認待ちタブ: 各請求書に「承認」「差し戻し」ボタン。コメント入力欄あり
  • 差し戻しタブ: 「OCR確認画面へ戻す（再確認申請）」ボタン（reconfirmアクション）
  • 承認・差し戻し時にSESメール通知をトリガー（notify_sender Lambda を非同期呼び出し）

3.5 ステータス一覧（list.html）

  • 全請求書をDynamoDBからスキャンして表示
  • 月別フィルター・ステータスフィルター
  • 請求書番号をクリックするとS3 Presigned URLでPDFを開く
  • CSVエクスポート機能
  • 「詳細」ボタン（スタブ・未実装）

3.6 ダッシュボード（dashboard.html）

  • 集計サマリー: 今月の請求書数・合計金額・承認待ち件数・差し戻し件数
  • 差し戻し処理待ちタスク一覧（rejectedステータスの請求書）
  • 最近の請求書一覧（直近10件）

3.7 管理者設定（settings.html）

  • 一般設定タブ: 会社名・会計年度・タイムゾーン（UI実装済み・保存API未接続）
  • OCR設定タブ: エンジン切り替えトグル4項目（UI実装済み・API未接続）
  • 承認ルールタブ: ルール一覧・追加モーダル（スタブ）
  • 通知設定タブ: メール/Slack/Teamsトグル・Webhook URL（API未接続）
  • ユーザー管理タブ: ユーザー一覧（ダミーデータ）・招待機能（スタブ）
  • 開発用ツール: 全履歴クリアボタン（本番前削除）

ビジネスロジック・業務ルール

▼

ステータスフロー（正式版）

アップロード
  └→ [processing]   ← S3アップロード時に presign_handler が DynamoDB登録
        │
        └→ [processing]   ← OCR完了時に ocr_trigger が各フィールドを更新
              │
              └→ [pending_approval]   ← ユーザーがOCR確認後に「承認申請」
                    │
                    ├→ [approved]   ← 承認者が「承認」
                    │
                    └→ [rejected]   ← 承認者が「差し戻し」
                          │
                          └→ [processing]   ← ユーザーが「再確認申請 (reconfirm)」
                                             → OCR確認画面に戻る
差し戻し（rejected）は「削除」ではなく「巻き戻し」。archive アクションは廃止済み。

OCRエンジン切り替えルール

  • アップロード時にユーザーが選択したエンジン名（"textract" or "claude"）をDynamoDB Invoices.ocrEngine フィールドに保存
  • ocr_trigger Lambda がこのフィールドを読み取り、処理を分岐
  • Textract: Seoul（ap-northeast-2）リージョン使用（ap-northeast-1 未対応）
  • Claude Vision: PDFをPyMuPDFでPNG変換 → base64 → Claude API（claude-opus-4-7）

承認ルール

  • 承認・差し戻し操作は pending_approval ステータスの請求書のみ可能
  • 再確認申請（reconfirm）は rejected ステータスの請求書のみ可能
  • 承認・差し戻し時はApprovalLogsテーブルにログを記録
  • 承認時・差し戻し時にアップロード者へメール通知（SES）

通知ルール

  • 通知対象: 承認（approved）・差し戻し（rejected）のアクション時
  • 通知先: uploadedBy（アップロードしたユーザーのメールアドレス）
  • 現状: SESサンドボックス中のため検証済みアドレス宛のみ送信可能

技術スタック

▼
カテゴリ技術選定理由
フロントエンド HTML / CSS / Vanilla JavaScript フレームワーク不要。軽量・高速開発可能。Amplifyで静的ホスティング
バックエンド Python 3.12（AWS Lambda） サーバーレス。コスト最小化。boto3でAWSサービスと親和性高い
データベース Amazon DynamoDB サーバーレス・スキーマレス。請求書データの柔軟な構造に適合
認証 Amazon Cognito JWT管理・ユーザープール・MFA対応をマネージドで提供
ファイルストレージ Amazon S3 Presigned URLで安全なPDF保管。S3トリガーでOCR自動起動
OCR（A） Amazon Textract（ap-northeast-2） 日本語請求書への高精度対応。Seoul リージョン使用（東京未対応）
OCR（B） Anthropic Claude Vision（claude-opus-4-7） 複雑レイアウト・手書き混在への柔軟対応。SSMでAPIキー管理
APIゲートウェイ Amazon API Gateway（REST API） HTTPS・CORS・Cognito Authorizer統合。Lambda統合でCORS安定
メール通知 Amazon SES AWS内でメール送信。Lambda非同期呼び出しで承認通知を送信
ホスティング AWS Amplify GitHubからCI/CDデプロイ。Cognito認証との統合が容易
シークレット管理 AWS SSM Parameter Store（SecureString） Anthropic APIキーをLambdaから安全に取得。ハードコード不要

  • 認証: Amazon Cognito JWT（idToken）。API Gateway Authorizer で全エンドポイント保護

  • 通信: HTTPS 必須（Amplify・API Gateway ともに）
  • IAM 最小権限: 各 Lambda に必要なポリシーのみ付与
  • 入力検証: Lambda 側で必須パラメータチェック・ステータス整合性チェック
